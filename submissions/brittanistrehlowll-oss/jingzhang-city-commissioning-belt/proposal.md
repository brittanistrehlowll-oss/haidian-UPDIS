# 京张·城市联调带
## JING-ZHANG CITY COMMISSIONING BELT
### AI时代的城市规划与真实场景创新｜Urban Planning and Real-World Innovation for the AI Era

**一句话方案：** 百年前，京张铁路改变了城市的物理连接；今天，AI正在改变城市的生产、生活和运行方式。本方案不为AI另划一块“科技用地”，而是在传统城市规划之上提出 **Civic AI Overlay｜城市AI叠加管控层**：让算力接口、运行权限、人工入口、数据与模型版本、复验条件和退出机制能够被规划表达，并在众智园、AI原点社区和大钟寺的真实场景中被验证、修正和持续使用。

> 本方案全部空间落位均为开放共创的概念建议。当前采用主办方仓库维护的 provisional_rough 临时边界，不代表官方红线；官方 polygon、控规、权属、文保和工程资料补齐后，所有面积、比例和地块级判断均须复核。 [source:BOUNDARY-SOURCE] [standard:PROJECT-OFFICIAL-ANNOUNCEMENT]

### 城市没有标准答案：让人类智慧与硅基智慧共同指向更美好的生活

人生没有标准答案，城市更没有标准答案。城市的意义不在于被某个规划师、机构或算法一次性“求解”，而在于让生活在其中的人能够持续感受、选择、创造和修正。过去，城市主要承载并放大人类的经验、制度与工程智慧；未来，来自人工智能系统的感知、计算、推理和协作能力，也会越来越深地参与城市。我们不把两者设成竞争关系，也不把AI设成替居民作出价值判断的“超级大脑”。**人类的智慧和硅基的智慧，都希望让我们的生活更加美好。** 人类提供价值、经验、伦理、情感、责任和最终判断；硅基智慧提供规模化感知、复杂推演、实时协同与持续学习。二者共同服务的对象，不是技术本身，而是人的生活、城市的公共利益与长期韧性。

共同目标不等于无限授权。C0-C6七道联调门因此从技术验收机制进一步成为城市的选择权机制：每一个AI建议先被视为假设，再经过模拟、规则与公共利益校核、影子运行、有限真实负载和人工监督，证据不足就停、风险不可控就退、公众利益不成立就不做。**智慧可以增加，权力边界必须清楚；系统可以越来越聪明，城市必须始终保留人的选择权。** 我们不是让AI替城市决定未来，而是让城市多一种理解自己、改善自己、与居民共同成长的能力。百年京张的下一段历史，不是简单地从钢轨走向算法，而是让人类智慧与硅基智慧第一次在真实城市中，共同服务于更美好的生活。 [standard:PROJECT-AGENT-OPEN-CALL-TASKBOOK] [depth:risk_missing_data]

## 设计依据与资料清单

本方案的正式任务依据来自主办方公告、仓库 `design_brief`、面向智能体任务书、公共资料登记表和临时边界。方案方法同时吸收既有城市规划、市政基础设施、韧性城市、AIDC投产联调、AI赋能控规、城市更新与地下空间研究经验，但不把任何内部客户底图、非公开指标或项目成果上传至公共仓库；只迁移可普适的方法论。 [source:OFFICIAL-ANNOUNCEMENT] [source:AGENT-TASKBOOK] [source:SOURCE-REGISTRY]

核心专业判断收敛为三条：第一，**AI场景和城市设计是主体**，基础设施与治理机制必须服务场景而不能取代场景；第二，AI进入城市后，规划需要新增一层可机器读取、可审查、可迭代的 **Civic AI Overlay**，用于表达传统控规难以描述的算力接口、运行权限、人工等价路径、责任与复验/退出条件；第三，AI基础设施不追求中心城区“大建数据中心”，而重点解决 **算力匹配、算电协调、算水协调** 三个AI时代的新型空间适配问题。C0-C6七道门和Evidence Ledger保留为运行方法，而不再承担方案第一原创点。 [standard:PROJECT-AGENT-OPEN-CALL-TASKBOOK] [depth:existing_conditions_diagnosis]

## 三层范围工作框架

**43.6km²统筹研究范围｜CITY SYSTEM。** 按公告北五环—京藏高速—西直门外大街—万泉河路的城市级范围，研究AI科研、产业、人才、算力能源、公共服务与真实场景反馈如何形成闭环。该层使用公告文字面积和任务关系，不以临时 polygon 进行法定面积推定。 [source:OFFICIAL-ANNOUNCEMENT]

**约11.4km²总体设计范围｜CITY COMMISSIONING DISTRICT。** 以京张遗址公园及周边1-2公里城市地区为主要空间载体，形成连续公共脊、东西缝合节点、AI基础设施接口、市政韧性网络与更新项目体系。提交边界由主办方 provisional geometry 复算为约11.41km²，仅用于设计模型。 [data:geometry/site_boundary.geojson#SITE-001] [metric:site_area_sqm]

**三处重点区域约368.4ha｜CITY LABS。** 众智园、北京AI原点社区、大钟寺分别承担“测试验证—真实日常负载—更新规则转化”三种不同任务。三处 polygon 均为临时粗略范围，其边不代表道路或地块红线。 [data:geometry/key_areas.geojson#PROV-KEY-001] [metric:key_area_count]

## 统筹研究范围产业与未来城市研究

### 1. 总体结构：城市设计主体 + Civic AI Overlay + AI基础设施适配 + 联调方法

**城市设计主体。** 京张遗址公园作为公共空间、文化和创新交流主脊，连接众智园、北京AI原点社区和大钟寺三个重点区，并与中关村科技服务翼、小月河场景赋能翼形成任务回路。空间叙事首先回答“人在这里怎样工作、生活、交流、更新”，其次才回答AI如何介入。方案不把京张做成连续科技展廊，也不以铁路隐喻替代真实城市设计。 [standard:MOHURD-URBAN-DESIGN-MEASURES]

**第一规划创新：Civic AI Overlay｜城市AI叠加管控层。** 传统控规表达用地、强度、道路、设施和公共空间；AI时代还出现了一组需要进入规划表达的新对象：边缘算力接口、场景算力等级、感知/服务空间范围、自动系统运行权限、人工等价入口、数据与模型版本、影子运行条件、复验触发与退出条件。Civic AI Overlay不替代法定控规，而是作为可供专业团队深化的叠加规则原型。每条规则采用：`Rule ID → Spatial Scope → Object → Requirement/KPI → Source → Responsible Party → Permission → Commissioning Gate → Evidence → Version → Re-test Trigger → Rollback/Exit`。

**专业支撑专项：AI Infrastructure Support｜AI基础设施适配系统。** 本方案不建立宏大的“六网”总体叙事，只聚焦三个与AI产业和城市空间直接相关的问题：**C｜Compute Matching 算力空间匹配；P｜Compute–Power Coordination 算电协调；W｜Compute–Water Coordination 算水协调**。通信、地下市政、交通和物流仍作为必要工程与场景适配条件，但不作为独立原创主线。

**运行方法：C0-C6 + City Evidence Ledger。** 七道联调门保留为“从概念到真实城市”的验证流程：C0资料与责任基线、C1模拟、C2规划/工程/公共利益规则校核、C3影子/假负载、C4有限真实负载、C5人工监督运行、C6复验/回滚/退出。Evidence Ledger记录空间范围、责任、数据/模型版本、权限、证据、失败事件和复验触发。它们负责让方案可验证，而不再作为标题级原创。

### 2. 世界级AI创新生态：从“企业集聚”升级为“真实城市验证能力”

京张的稀缺性不应只是聚集更多AI企业，而是提供 **Research → Test → Limited Deployment → Daily Use → Evidence → Rule Update → Re-test** 的真实城市创新闭环。众智园输出测试证据和接口标准，AI原点社区提供真实生活负载，大钟寺把证据转成更新规则和项目机制，中关村科技服务翼提供科研、IP、资本、模型与标准服务，小月河场景赋能翼提供生态、社区、市政与公共服务反馈。 [source:AGENT-TASKBOOK] [metric:ecosystem_case_count]

## 总体设计范围城市更新与控规深度城市设计

总体设计不把AI设施叠加到一张普通城市设计上，而把物理基础设施、公共空间和治理规则作为同一设计对象。用地模型使用统一国土空间用地代码，形成科研—公园绿地—商业服务—社区服务的概念功能梯度；它只证明结构化表达和空间接口，不代表审定用地。 [data:geometry/land_use.geojson#LU-001] [standard:MNR-LAND-USE-CLASSIFICATION-GUIDE]

**Civic AI Overlay三类规则：**
- A Mandatory：安全、隐私、公共利益、人工接管、审计、应急不得绕过；
- B Conditional：允许以等效性能满足的条件性要求；
- C Guidance/Experimental：试点、创新和未来迭代。
每条规则采用 `Rule ID + Spatial Scope + Object + Requirement/KPI + Source + Responsible Party + Approval Gate + Version + Evidence + Re-test Trigger + Rollback/Exit`。

**更新策略：** 采用“体检—协商—策划—行动—联调—复验”的渐进更新逻辑。现阶段只给出保留适应、改造开放、新建测试设施、临时可逆使用四类概念动作；缺乏权属、结构、历史价值和法定控制条件时，不指定具体拆除建筑。 [standard:MOHURD-CONTROL-DETAILED-PLANNING] [depth:retain_renovate_demolish]

## 重点区域详细设计

![三处重点区域：测试验证、真实负载、更新规则](assets/figures/key-areas.png)

### A. 众智园｜CITY TESTBED
定位为“AI研发成果进入真实城市前的测试验证区”。空间模块以开放测试场、机器人/自主系统测试路网、开发者共享设施和AI基础设施接口为主。基础设施重点不是建设大型训练型AIDC，而是提供**高可靠算力接口、测试算力、边缘节点、算电协调、储能与机器人充换能条件**。三类关键测试分别为 ICT/算力/终端互操作、机器人与自主物流物理场、市政AI影子运行与故障恢复。测试通过只形成证据，不自动等于获得城市运行许可。 [data:geometry/key_areas.geojson#PROV-KEY-001]

### B. 北京AI原点社区｜LIVING LOAD
定位为世界级AI人才社区和公共AI服务的真实日常负载区。设计优先住房、教育、健康、社区、无障碍、通勤、创新首层和夜间生活；基础设施重点是**边缘推理、低时延公共服务、低侵扰感知和应急供能**，而不是把社区变成设备展场。基本公共服务不以注册商业AI账号为前提，关键服务同时保留 **AI入口 / 人工入口 / 离线入口 / 低感知路径**，不以强制数据授权换取基本城市服务。 [data:geometry/key_areas.geojson#PROV-KEY-002] [standard:BARRIER-FREE-ENVIRONMENT-LAW]

### C. 大钟寺｜RENEWAL RULE LAB
定位为全案最具规划专业含量的“**AI更新单元详规工作台**”。左侧输入居民、产权主体、政府、运营者和公共服务需求；中部把诉求转译为空间变量、公共利益约束、实施条件和多方案推演；右侧形成A/B/C规则、更新项目、临时利用/正面清单、实施状态和复验记录。工作流采用 **体检评估 → 多主体协商 → 片区—地块校核 → 公共利益校核 → 规则生成 → 更新项目 → 分阶段实施 → 一张图维护 → 复验**。基础设施重点是**存量建筑算力适配、共享推理服务、低成本接入和增量容量控制**。AI可以推演，但不能自动决定容积率、产权、拆迁或替代法定公众参与。 [data:geometry/key_areas.geojson#PROV-KEY-003] [depth:three_key_area_detailed_design]

## AI 创新生态、人才画像与 AI+ 场景

**8类用户画像不是装饰性故事，而是系统的“真实负载”与失败判据：**

|人物|最关心的城市任务|AI应做什么|不能接受的失败|
|---|---|---|---|
|AI科研/开发者|测试模型、终端、机器人与接口|提供可复现测试环境和证据|测试通过被误写成城市准入|
|创业团队/企业|低成本验证产品和寻找真实需求|提供接口、场地、合规路径和失败反馈|只有展示机会，没有可验证真实负载|
|居民与家庭|通勤、教育、健康、社区与休闲|降低办事和信息成本|基本服务被商业账号或强制数据授权绑架|
|老人/残障人士|无障碍出行、人工帮助和可靠服务|提供可解释导航、状态信息和人工转接|断网/模型失败后服务完全消失|

## 交通、轨道与 AI基础设施适配

![交通慢行、蓝绿与AI基础设施适配](assets/figures/mobility-bluegreen.png)

**交通与公共空间首先服务人。** 京张公共脊优先形成连续步行/自行车系统，并在三处重点区附近设置东西向缝合节点。路缘空间可按上下客、配送、自主物流、应急和活动进行时分共享；自动驾驶/机器人测试必须有明确地理围栏、测试时段和人工接管。通信、地下市政、物流系统按常规专业要求进行冗余、维护和接口预留，不上升为本方案独立概念。

### AI Infrastructure Support｜AI基础设施适配系统

本专项只回答一个问题：**京张需要什么样的算力，如何在核心城区的电力、水资源和空间条件下合理承载它？** 方案采用 `Compute–Power–Water Nexus`，中间是 **AI Workload Orchestration｜AI负载协同**。所有容量均为规则和接口层建议，不虚构MW、管径、供水量或既定工程线位。 [depth:municipal_public_services]

**C｜Compute Matching｜算力空间匹配。** 建立三级体系：①区域算力承担大模型训练和高强度计算，原则上更多依托核心城区外部资源；②片区级算力服务承担推理、数字孪生、城市模型、科研开发和企业共享服务；③边缘算力节点靠近众智园、AI原点、公共空间和市政场景，承担低时延、隐私敏感和高可靠任务。规划判断不是“哪里能塞进数据中心”，而是**什么场景需要什么等级的算力，什么任务必须本地，什么任务可以区域协同**。

**P｜Compute–Power Coordination｜算电协调。** 从“预测负荷—配电设施”升级为“**算力任务 × 电力状态 × 储能 × 建筑柔性负荷 × 时间**”。负载分为：①保障负荷——应急、关键公共服务和安全相关AI；②可调负荷——普通推理、企业计算、充电等可在时间上调整；③可迁移负荷——可转移到区域算力中心的训练或批处理任务。规划关注可调度能力而不是虚构总容量，关键场景应有降级和应急供能策略。

**W｜Compute–Water Coordination｜算水协调。** 中心城区新增算力必须接受水资源和热环境约束。建立四级空间适配规则：**W0** 边缘微节点，基本不形成显著新增冷却水需求；**W1** 中小型算力设施，优先低水耗/闭式冷却；**W2** 高密度算力，必须同步论证能源、水资源、热排放和余热利用条件；**W3** 高耗水、高耗能且不需要本地低时延的计算任务，原则上通过区域协同供给。该分级是概念性准入框架，不替代专项水资源、能源或工程论证。

**三个重点区的差异化适配：** 众智园侧重高可靠测试算力、算电协调和机器人充换能；AI原点侧重边缘推理、低侵扰感知和应急供能；大钟寺侧重存量建筑算力适配、共享算力服务和增量容量控制；京张公共脊仅布置小型复合边缘节点，不建设“设备走廊”。

## 蓝绿空间、公共空间与城市风貌

**公共利益直接转成空间验收标准。** 对关键公共AI服务，要求同一地点能够识别并到达 **AI入口 / 人工入口 / 离线入口 / 低感知或无感知路径**；没有商业账号仍可获得基础服务，断网或模型失效后仍保留基本功能，无障碍用户、老人和低数字技能人群应完成同一套服务验收。这不是伦理宣言，而是公共空间和服务节点的设计条件。 [standard:BARRIER-FREE-ENVIRONMENT-LAW] [depth:blue_green_public_space]

京张遗址公园是“开放创新与公共审计脊”，而不是科技展廊。城市风貌强调真实街道、树荫、低门槛公共空间、铁路遗产连续叙事和小尺度数字界面。建筑体量采用“沿公共脊开放、重点节点形成识别、重点区内部适应产业需求”的原则，不在缺乏控规和文保资料时给出高度数值。 [standard:MOHURD-URBAN-DESIGN-MEASURES] [depth:blue_green_public_space]

4个AI朝圣/公共荣誉节点均为概念工作名：
1. **First Run Yard｜首发试运行场**：铁路试运行历史与AI城市联调起点叠加；
2. **Open Evidence Hall｜开放证据厅**：展示开源方案、规则、数据来源、版本、贡献者和测试证据；
3. **Civic Override Beacon｜公共接管灯塔**：以可理解方式展示“AI有限权限、人类最终责任、系统可退出”；
4. **Commissioning Commons｜联调共享场**：开发者、居民、运维者共同测试和反馈的公共空间。 [metric:ai_landmark_count]
