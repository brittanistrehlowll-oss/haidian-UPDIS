# 京张·城市联调带
## JING-ZHANG CITY COMMISSIONING BELT
### AI时代的城市规划与真实场景创新｜A CIVIC AI OVERLAY FOR THE AI-NATIVE CITY

**一句话方案：** 百年前，京张铁路以测量、工程标准、试运行和复核建立可靠的物理连接；今天，AI正在改变城市的生产、生活和运行方式。本方案不为AI另划一块“科技用地”，而是在传统城市规划之上提出 **Civic AI Overlay｜城市AI叠加管控层**：让算力接口、运行权限、人工入口、数据与模型版本、复验条件和退出机制能够被规划表达，并在众智园、AI原点社区和大钟寺的真实场景中被验证、修正和持续使用。

> 本方案全部空间落位均为开放共创的概念建议。当前采用主办方仓库维护的 provisional_rough 临时边界，不代表官方红线；官方 polygon、控规、权属、文保和工程资料补齐后，所有面积、比例和地块级判断均须复核。 [source:BOUNDARY-SOURCE] [standard:PROJECT-OFFICIAL-ANNOUNCEMENT]

### 城市没有标准答案：让人类智慧与硅基智慧共同指向更美好的生活

人生没有标准答案，城市更没有标准答案。城市的意义不在于被某个规划师、机构或算法一次性“求解”，而在于让生活在其中的人能够持续感受、选择、创造和修正。过去，城市主要承载并放大人类的经验、制度与工程智慧；未来，来自人工智能系统的感知、计算、推理和协作能力，也会越来越深地参与城市。我们不把两者设成竞争关系，也不把AI设成替居民作出价值判断的“超级大脑”。**人类的智慧和硅基的智慧，都希望让我们的生活更加美好。** 人类提供价值、经验、伦理、情感、责任和最终判断；硅基智慧提供规模化感知、复杂推演、实时协同与持续学习。二者共同服务的对象，不是技术本身，而是人的生活、城市的公共利益与长期韧性。

共同目标不等于无限授权。**Civic AI Overlay 是规划层，C0-C6只是运行层。** 规划先回答“AI在什么空间、以什么对象、调用什么城市资源、拥有多大权限、谁负责、失败后如何降级”，七道联调门再回答“这套能力怎样从模拟进入有限真实运行”。每一个AI建议都先被视为假设，再经过规则与公共利益校核、影子运行、有限真实负载和人工监督；证据不足就停、风险不可控就退、公众利益不成立就不做。**智慧可以增加，权力边界必须清楚；系统可以越来越聪明，城市必须始终保留人的选择权。** 我们不是让AI替城市决定未来，而是让城市多一种理解自己、改善自己、与居民共同成长的能力。 [standard:PROJECT-AGENT-OPEN-CALL-TASKBOOK] [depth:risk_missing_data]

## 设计依据与资料清单

本方案的正式任务依据来自主办方公告、仓库 `design_brief`、面向智能体任务书、公共资料登记表和临时边界。方案方法同时吸收既有城市规划、市政基础设施、韧性城市、AIDC投产联调、AI赋能控规、城市更新与地下空间研究经验，但不把任何内部客户底图、非公开指标或项目成果上传至公共仓库；只迁移可普适的方法论。 [source:OFFICIAL-ANNOUNCEMENT] [source:AGENT-TASKBOOK] [source:SOURCE-REGISTRY]

核心专业判断有三条：第一，**AI进入城市以后，详规需要新增规划对象**——边缘算力接口、能源柔性接口、机器人物流接口、感知边界、运行权限、人工接管和退出条件不能继续停留在“运营层备注”；第二，**中心城区的AI基础设施必须做空间适配，而不是默认新增大型数据中心**，重点判断不同任务需要何种算力、何时用电、何种冷却与用水约束，因此本方案把基础设施创新收敛为 Compute / Power / Water 三项；第三，**公共利益必须被空间化**，AI入口之外同时保留人工入口、离线入口和低/无感知路径。由此形成“城市设计主体 + Civic AI Overlay + C/P/W专业支撑 + C0-C6运行方法”的清晰层级。 [standard:PROJECT-AGENT-OPEN-CALL-TASKBOOK] [depth:existing_conditions_diagnosis]

## 统筹研究范围产业与未来城市研究

本方案先服从官方任务结构，再提出自己的规划创新。三大定位分别对应 **百年京张文化带、都市AI生活体验带、AI融合创新带**；五大功能分别对应 **AI全栈自主创新体系、世界级AI创新生态、AI+场景赋能新范式、智能化AI活力城市、AI治理全球话语权**。空间上以京张遗址公园公共脊串联三重点区，并通过中关村科技服务翼与小月河场景赋能翼把科研、专业服务、社区、市政和真实城市场景接入同一闭环。 [source:AGENT-TASKBOOK] [standard:PROJECT-AGENT-OPEN-CALL-TASKBOOK]

### 1. 城市设计主体：公共脊 + 三重点区 + 三区两翼

**京张公共脊**首先是日常公共空间、慢行网络和百年铁路文化载体，其次才是AI界面。沿线数字设施小型化、可解释、可退出，与遮阴、休息、应急、导航和公共服务复合，不建设连续巨型“科技展示墙”。 [standard:MOHURD-URBAN-DESIGN-MEASURES]

三重点区不是三个孤立园区，而是一条 **技术验证 → 真实生活负载 → 更新与商业规则转化** 的调测功能链：
- **众智园 CITY TESTBED**：验证设备、机器人、接口和市政AI进入真实城市前的可靠性与边界；
- **北京AI原点社区 LIVING LOAD**：把住房、教育、健康、社区、无障碍和通勤作为真实日常负载，验证AI是否真正改善生活且不排斥非数字路径；
- **大钟寺 RENEWAL RULE LAB**：把测试和使用证据转化为存量更新规则、项目清单、商业与公共空间运营条件，并服务站城复合、高并发消费与更新场景的规划校核，但不预设具体TOD工程方案或法定开发强度。

这条链条保留外部意见中“研发—验证—转化”的优点，但不把官方片区名称改写成未经确认的新名称，也不把商业转化凌驾于公共利益与法定程序之上。 [depth:overall_spatial_structure]

### 2. Civic AI Overlay｜AI时代的详规叠加管控层

**Civic AI Overlay 是本方案第一规划创新。** 传统详规继续负责用地、开发强度、道路、设施、公共空间和城市风貌；Overlay补充AI进入城市后新增的规划对象：边缘算力接口、场景算力等级、感知/服务空间范围、自动系统运行权限、人工等价入口、数据/模型版本、影子运行条件、责任主体、复验触发和回滚/退出。

最小规则单元为：

`Rule ID → Spatial Scope → Object → Requirement/KPI → Source → Responsible Party → Permission → Commissioning Gate → Evidence → Version → Re-test Trigger → Rollback/Exit`

规则分为：
- **A Mandatory**：安全、隐私、公共利益、人工接管、审计与应急等不可绕过底线；
- **B Conditional**：满足明确前置条件或等效性能后才允许进入下一阶段；
- **C Guidance / Experimental**：试点、创新和可迭代建议。

它是详细规划的叠加原型，不是新设法定“AI用地”，也不替代控规、审批或真实公众参与。 [depth:professional_evidence_chain]

### 3. AI Infrastructure Support｜Compute–Power–Water Nexus

基础设施创新只强化三项与AI负载直接相关的专业关系：

**C｜Compute Matching。** 采用“区域算力—片区共享服务—边缘节点”三级匹配。规划判断不是“哪里建数据中心”，而是区分哪些任务必须本地低时延、哪些可由片区共享、哪些训练或批处理负载应由区域资源承担。

**P｜Compute–Power Coordination。** 关注 `AI workload × power condition × storage × flexible building load × time`。保护型负载优先保障，柔性负载可移峰，迁移型负载可转向区域算力。当前不虚构MW、MVA、储能规模或设备容量。

**W｜Compute–Water Coordination。** 采用 W0–W3 概念适配等级：从几乎不新增冷却用水的边缘微节点，到需要联合论证能源、冷却、用水、散热与余热利用的高密度算力；若无本地时延必要且资源条件不足，应优先区域化。当前不虚构水量、管径或工程线位。

通信、地下市政、交通物流继续作为普通工程适配条件，不再包装成独立“六张网”原创点。 [depth:municipal_new_infrastructure]

### 4. 城市调测与双轨安全：从“可运行”到“可退出”

“City Commissioning”在本方案中不是让城市长期处于试验状态，而是把真实运行前后的 **证据、权限、人工接管和退出** 制度化。C0-C6只作为运行方法：
C0证据基线 → C1模拟 → C2规则校核 → C3影子/假负载 → C4有限真实负载 → C5人工监督运行 → C6复验/回滚/退出。

外部建议中的“双轨制”被收敛为 **AI增强层与常规城市基底解耦**：AI能力失效时，服务应按已设计的 DEGRADED / MANUAL / EXIT 路径降级；但本方案不承诺“全网断电仍零影响”或“毫秒级平滑切换”，真实切换时间和保障等级必须由专业工程设计与运营演练确定。

### 5. 世界级AI创新生态：从企业集聚到真实城市验证能力

京张的稀缺性不只是更多AI企业，而是提供 **Research → Test → Limited Deployment → Daily Use → Evidence → Rule Update → Re-test** 的真实城市创新闭环。众智园输出测试证据和接口问题，AI原点提供真实生活反馈，大钟寺把证据转成更新与运营规则；中关村科技服务翼提供科研、IP、资本和专业服务，小月河场景赋能翼提供生态、社区、市政和公共服务反馈。 [metric:ecosystem_case_count]

七个国际机制案例仅作背景比较：EU CitCom.ai 的真实城市测试设施；新加坡 Punggol Digital District 的开放数字平台与数字孪生；Helsinki / Forum Virium 的 Living Lab；Paris-Saclay DataIA 的科研—人才—创新连续体；Toronto Vector Institute 的研究工程化与产业采用；London Knowledge Quarter 的机构密度与可步行创新街区；监管沙盒的有限范围、持续监测和可暂停机制。京张只提取机制，不声称合作、认证或政策复制。

### 6. 品牌与传播

主名称保持 **京张·城市联调带｜JING-ZHANG CITY COMMISSIONING BELT**。核心识别采用“叠加层 / 接口 / 状态 / 证据”的图形语法，铁路工程史只作为“测量—试运行—复核—真实运营”的文化背景，不把“人字形线路”或历史细节强行转化成空间造型。**PROVE BEFORE SCALE** 与 **HUMAN OVERRIDE BY DESIGN** 保留为运行原则。

## 总体设计范围城市更新与控规深度城市设计

总体设计不把AI设施叠加到一张普通城市设计上，而把 **公共空间、存量更新、AI时代规则对象与C/P/W适配** 作为同一设计问题。用地模型采用统一国土空间用地分类形成科研—公园绿地—商业服务—社区服务的概念功能梯度，只用于证明结构和接口，不代表审定用地。 [data:geometry/land_use.geojson#LU-001] [standard:MNR-LAND-USE-CLASSIFICATION-GUIDE]

![用地结构：科研、公园绿地、商业服务与社区服务的概念功能梯度](assets/figures/land-use-structure.png)

**Civic AI Overlay规则分A/B/C三类**，每条规则保留来源、责任、权限、版本、证据、复验触发和退出条件。凡涉及强度、高度、产权、拆迁、文保、市政容量等法定或工程判断，在资料不足时保持 unknown / to verify，不让AI把缺失数据补成“看起来完整”的规划指标。 [depth:land_use_layout]

**更新策略**采用“体检—协商—策划—行动—联调—复验”的渐进逻辑。现阶段只给出保留适应、改造开放、新建测试设施、临时可逆使用四类概念动作；缺乏权属、结构、历史价值和法定控制条件时，不指定具体拆除建筑。 [standard:MOHURD-CONTROL-DETAILED-PLANNING] [depth:retain_renovate_demolish]

**模块化城市联调舱（City Commissioning Pod）**作为空间原型，仅在需要时复合边缘推理、能源接口、公开感知告知、人工求助和物理停用能力。其数量、间距、设备功率、储能规模和具体构造不在本阶段设定；正式工程条件到位后再选址和定型。这样吸收“模块化、可插拔、可迁移”的工程思路，同时避免把概念原型伪装成施工图。

## 重点区域详细设计

![三处重点区域：测试验证、真实负载、更新规则](assets/figures/key-areas.png)

### A. 众智园｜CITY TESTBED
定位为AI城市系统进入真实城市前的开放测试与验证区。空间模块包括开放测试场、机器人/自主系统测试路网、边缘算力与通信节点、能源接口、模型安全与治理实验室、开发者共享设施。三类关键验证为 ICT/算力/终端互操作、机器人与自主物流物理测试、市政AI影子运行与故障恢复。测试通过只形成证据，不自动等于获得城市运行许可。 [data:geometry/key_areas.geojson#PROV-KEY-001]

外部建议中的“硬件中试”被吸收为 **多环境、可复现、可熔断的测试条件**，但本阶段不写高低温舱、电磁兼容舱、固定环线尺度等未经场地与工程论证的设施配置。

### B. 北京AI原点社区｜LIVING LOAD
定位为世界级AI人才社区与公共AI服务的真实日常负载区。住房、教育、健康、社区、无障碍、通勤、首层创新业态和夜间生活先成立，AI再叠加。关键公共服务形成四条等价路径：**AI入口 / 人工入口 / 离线入口 / 低或无感知路径**；基础服务不以商业AI账号或持续感知授权为前提。 [data:geometry/key_areas.geojson#PROV-KEY-002] [standard:BARRIER-FREE-ENVIRONMENT-LAW]

“算法透明”被转化为可见的公共解释界面：公开说明传感对象、数据用途、模型/规则版本、责任主体和人工申诉路径，而不是把居民区变成持续展示技术的“实验场”。

### C. 大钟寺｜RENEWAL RULE LAB
大钟寺是本方案最具规划专业含量的 **AI更新单元详规工作台**，同时承接站城复合、AI原生消费、企业服务和高并发公共活动的规则校核。它要证明的不是“AI能自动生成更新方案”，而是存量城市如何把多主体诉求、公共利益、片区—地块约束、商业运营与实施状态转成可追踪的详规规则。

工作流采用：**体检评估 → 多主体协商 → 片区—地块空间/经济校核 → 公共利益校核 → A/B/C规则生成 → 更新项目清单 → 临时利用/正面清单 → 分阶段实施 → 一张图维护 → 复验。**

输出分为：
- **规则**：公共利益底线、接口要求、可逆使用条件、人工/离线服务要求；
- **项目**：公共空间补短板、适应性再利用、步行缝合、可逆创新空间、站城复合服务；
- **状态**：待核实、可试点、需专业审查、需法定程序、暂不实施。

外部建议中的“高并发商业调测”被吸收为场景和运营规则，但不直接承诺下沉广场、无人机巢、Robo-Shuttle同层换乘等具体工程，也不自动决定FAR、权利、补偿或拆迁。 [data:geometry/key_areas.geojson#PROV-KEY-003] [depth:three_key_area_detailed_design]

## 交通、轨道、市政与公共服务设施

![交通慢行、蓝绿、市政与AI基础设施复合系统](assets/figures/mobility-bluegreen.png)

### Commissioning Right-of-Way｜分级分权的调测路权

本方案吸收“三维分层路权”的思路，但不在缺乏交通、低空和工程依据时虚构固定高度、宽度或航线。空间原则为：
- **公共慢行主脊优先**：步行、自行车、无障碍和日常公共生活拥有最高公共性；
- **低速机器人/配送测试为条件性路权**：只在明确地理围栏、时段、速度、运营责任和人工接管条件下进入限定路段，可采用独立、时分或共享组织，由后续交通设计确定；
- **机动车与应急系统保持常规城市交通逻辑**，AI测试不能削弱消防、救护、公交和日常通勤；
- **低空与地下接口仅作 CONDITION-BASED 预留**：是否设置无人机物流、地下微管廊或专用散热/能源通道，应在空域、安全、文保、市政容量和工程可行性明确后再深化。

三处概念东西缝合点承担跨越城市断点的慢行和公共空间联系，但不把它们直接定义为必须新建的“调测天桥”；最终采用平交优化、桥、隧或复合方式由正式道路、轨道、权属和工程条件决定。 [data:geometry/roads.geojson#ROAD-X01] [depth:traffic_rail_slow_parking]

### C/P/W基础设施适配

**Compute：** 区域算力承担训练和可迁移批处理，片区共享服务承担城市模型/科研/企业推理，边缘节点只服务低时延、隐私敏感或高可靠场景。

**Power：** 按 Protected / Flexible / Migratable 三类负载组织调度逻辑，保护公共安全和关键服务，柔性负载移峰，迁移型计算转移；不虚构供电容量。

**Water：** W0–W3作为冷却与用水约束的规划适配等级，高密算力只有在能源、用水、散热和余热利用条件共同成立时才可进入；没有本地时延必要的高耗资源任务优先区域化。

**通信与地下市政**继续采用多路径、关键节点冗余、可维护和故障隔离原则。所有AI接口都必须能在故障时从增强状态退回人工或常规运行，不把“预测能力”误写成“自动控制权”。 [depth:municipal_new_infrastructure]

### 公共利益作为空间标准：四条等价路径

凡承载基础公共服务的AI节点，原则上同时设计：
1. **AI入口**：允许主动使用智能服务；
2. **人工入口**：现场窗口、值守或人工转接可被直接看见；
3. **离线入口**：无账号、断网或模型不可用时仍能完成基础任务；
4. **低/无感知路径**：不愿进入持续感知环境的人仍能通行和使用公共空间。

这四条路径追求的是**基础公共服务结果等价**，而不是界面完全相同。典型验收包括轮椅用户能否完成同一任务、老人能否不用商业账号办理、断网后是否仍有基础功能、系统是否显示人工责任与投诉/申诉入口。 [standard:BARRIER-FREE-ENVIRONMENT-LAW] [depth:blue_green_public_space]

## 蓝绿空间、公共空间与城市风貌

京张遗址公园是 **开放创新与公共交流脊**，不是科技展廊。城市风貌强调真实街道、树荫、低门槛公共空间、铁路遗产连续叙事和小尺度数字界面。建筑体量采用“沿公共脊开放、重点节点形成识别、重点区内部适应产业需求”的原则，不在缺乏控规和文保资料时给出高度数值。 [standard:MOHURD-URBAN-DESIGN-MEASURES] [depth:blue_green_public_space]

**Digital Quiet / Low-Sensing Zones｜数字宁静与低感知空间。** 在居住、儿童、无障碍和生态敏感场景中，优先采用最小必要感知、明确告知和非识别技术；不把未经授权的人脸识别、持续身份追踪或深度扫描作为进入公共空间的默认条件。具体边界不在本阶段画成法定“红线”，由正式用途、隐私影响评估和运营责任共同确定。

公共节点采用 **3+1** 结构：
1. **First Run Yard｜首发试运行场**：把铁路工程的“试运行—复核—真实运营”文化转成AI城市联调起点；
2. **Open Evidence Hall｜开放证据厅**：公开规则、来源、版本、测试证据和失败记录；
3. **Civic Override Beacon｜公共接管灯塔**：让“AI有限权限、人工最终责任、可降级可退出”成为公众可理解的空间符号；
4. **Commissioning Commons｜联调共享场**：作为开发者、居民、运维者共同测试和反馈的支撑型共享场，不列入三大核心荣誉节点。 [metric:ai_landmark_count]
